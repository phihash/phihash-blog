スキル

anthropics/skills

  • 🛠️

    skill-creator

    スキルを新しく作ったり、既存のスキルを直したりする。テストを走らせて性能を測り、呼び出されやすいように説明文も調整する。
  • 📘

    docx

    Word 文書（.docx）を作成・読み取り・編集する。目次やページ番号の入った文書の作成、変更履歴やコメントの扱い、画像の差し替えなどに使う。
  • 📄

    pdf

    PDF の作業全般を行う。テキストや表の抜き出し、結合と分割、フォームの入力、透かしの追加、スキャンした PDF の文字認識（OCR）などに使う。
  • 📽️

    pptx

    PowerPoint（.pptx）のスライドを作成・読み取り・編集する。新しい資料作り、既存スライドの修正、テンプレートやスピーカーノートの扱いに使う。
  • 📈

    xlsx

    Excel などの表計算ファイル（.xlsx、.csv など）を開いて編集したり、新しく作ったりする。数式、書式、グラフ、崩れた表データの整理に使う。

mattpocock/skills

  • 🔥

    grill-me

    ざっくりしたアイデアを、エージェントが質問攻めにして詰めてくれるスキル。/grill-me で呼び出す。
  • ❓

    grilling

    計画やアイデアについてエージェントが質問を重ね、考えの甘い所を洗い出す。grill-me から呼ばれる、質問攻めの本体。
  • 📚

    grill-with-docs

    grill-me と同じ質問攻めをしながら、決めたことを ADR（設計判断の記録）と用語集に書き残す。コードを読んで、内容をコードベースに合わせる。

keitakn/engineering-skills

  • 🖼️

    explain-visually

    長い設計文書や PR、Issue を読み解き、図と短い文で説明する HTML を作ってブラウザで開く。気になる項目を指定すると、そこだけを掘り下げたページも作る。
  • 💬

    code-comments

    コード、テスト、コミットログ、コードコメントのどこに何を書くかを決める。コードには How、テストには What、コミットログには Why、コメントには Why not を書き分ける。
  • 🏷️

    code-naming

    変数や関数、クラスなどに名前を付けるときに使う。get を使いすぎず、何をして値を得るのかが名前から分かるようにする。
  • 🔁

    codex-plan-review-loop

    実装計画を Codex CLI にレビューさせ、指摘を仕分けて計画を直し、またレビューさせる流れを繰り返す。実装計画と要件のファイルを渡して使う。
  • 🔄

    codex-pr-review-loop

    GitHub の PR を Codex CLI にレビューさせ、指摘を仕分けてコードを直し、またレビューさせる流れを繰り返す。PR にリンクされた Issue なども必ず読んで確かめる。

TAKT

  • 🏗️

    j5ik2o-takt-workflow-builder

    要件を聞き取って、TAKT のワークフロー（YAML）を作成・カスタマイズする。ステップの構成とルールを決め、必要なファセットのファイルもまとめて作る。
  • 🔍

    j5ik2o-takt-analyzer

    TAKT（AI コーディングエージェントの作業の流れを YAML で決める CLI）のワークフローとファセット（各ステップでエージェントに渡す役割や指示のファイル）を分析して改善点を出す。実行ログがあればログからも診断する。
  • 🧩

    j5ik2o-takt-facet-builder

    各ステップでエージェントに渡すファセットを1つずつ作成・編集する。役割（ペルソナ）、ポリシー、指示（インストラクション）、知識（ナレッジ）、出力の形式（出力契約）の5種類がある。
  • ⚡

    j5ik2o-takt-optimizer

    TAKT のワークフローを最適化する。トークンの削減、ステップの統合、並列化などを行い、修正後のファイルを直接作る。
  • 📋

    j5ik2o-takt-task-builder

    TAKT に実行させるタスクを登録する。タスクの一覧（tasks.yaml）のエントリと、タスクごとの仕様書（order.md）を作成・編集する。

mizchi/skills

  • 🧪

    empirical-prompt-tuning

    スキルや CLAUDE.md など、エージェント向けの指示を改善する。別のエージェントに実際に実行させて評価し、少しずつ直していく。名前を指定して呼んだときだけ動く。
  • 🔎

    ast-grep-practice

    コードの構文で検索・置換する ast-grep を、プロジェクトの lint として使う。一般的な linter では書けないルールを作るときに使い、設定、自動修正、テスト、CI まで扱う。
  • 🏠

    chezmoi-management

    chezmoi で管理している mizchi さん本人の dotfiles を扱う。差分の確認と反映、スキルの追加、新しいマシンの初期設定などに使う。
  • 📐

    formal-methods-reconciler

    仕様、ドキュメント、テスト、コードの食い違いを形式手法で突き合わせる。Z3 や TLA+ などから合う検証ツールを選んで小さなモデルを作り、結果を開発者向けの問いや回帰テストに直す。
  • 📅

    frontend-review-weekly

    週1回のフロントエンドの AI レビューをまとめて回す。5つの観点のレビューを並列で実行し、先週の指標と比べた週次レポートを作る。ほかの frontend-review-* スキルと組み合わせて使う。
  • 🕸️

    multi-agent-orchestration

    サブエージェントを使うべきか、使うなら順番に回すか並列に広げるかを決める。エージェントを増やしてもトークンの無駄になる場面を見分けるのにも使う。
  • 🎭

    playwright-test

    Playwright の E2E テストの書き方と CI 設定のベストプラクティス集。固定の待ち時間を避ける方法、ドラッグ＆ドロップ、GitHub Actions での分割実行やリトライなどを扱う。
  • 📌

    retrospective-codify

    試行錯誤の末に解決した問題から「最初に知っていればよかったこと」を取り出し、ast-grep のルール、スキル、CLAUDE.md のルールとして残す。頼んだときだけ動く。
  • 🧭

    skill-finder

    手持ちのカタログにないスキルを、公式や有名なスキル集から探して評価する。採用する前に waxa-eval で品質を確かめる。
  • 🗂️

    skill-selector

    プロジェクトに必要なスキルを選んで apm.yml に設定する。まず厳選したカタログから選び、合うものがなければ外を探す。
  • 🧬

    stryker-js

    JavaScript/TypeScript のテストの質を、ミューテーションテストツールの StrykerJS で測る。コードを書き換えても落ちないテストを見つけ、足りないケースや弱いアサーションを探す。AI が書いたテストにも使える。
  • 👁️

    vlmkit

    画像を読める AI（VLM）でフロントエンドの見た目を確かめるツールキットの入口。HTML/CSS を変えたあとに見た目が変わったか、どこが変わったか、どの CSS が原因かを調べる。スクリーンショットからのマークアップ作成なども扱う。
  • 🚀

    void-app

    VoidZero の Void と Vite+ でフルスタックアプリを作る。特に Cloudflare D1 を使う React のアプリ向けで、雛形作成、型付きのローダー・アクション・フォーム、DB マイグレーション、テスト、デプロイ準備まで扱う。
  • 📊

    waxa-eval

    waxa CLI でスキルのプロンプトを評価しながら改善する。評価シナリオと採点方法の作り方や、改善を終える判断の仕方をまとめている。

その他

  • 🎯

    pm-skills

    プロダクトマネジメント用のスキル集。ディスカバリー、戦略、PRD作成、ローンチ計画などのPMフレームワークを、Claude Code で手順どおりに進められる。
  • 🤖

    gril-jev

    仕様や設計の決定について質問を重ねるが、答えるのはユーザーではなく Jev（typesafe-ai/jev）。決まった内容は ADR として残す。仕様のあいまいな所を決定として確定させたいときに使う。
  • 🎫

    ticket-work

    1つのチケットを、依頼内容の確認からプルリクエストのマージまで7つのステップで進める。機能の追加や変更、バグ修正、リファクタリングを始めるときに使う。1行の修正やドキュメントだけの変更には使わない。
  • 🛡️

    security-audit

    コードベース、API、CLI ツールなどのセキュリティを確認し、脆弱性を探す。セキュリティの質問や部分的なレビューにも使え、全体の監査は頼まれたときだけ行う。
  • ✍️

    write-blog-article

    日本語の技術ブログ記事を、調べて確かめてから下書きする。azukiazusa さんの記事の構成、文体、書式に合わせて書き、書き手がその技術を学べるようにする。
  • 🗓️

    nippo

    Claude Code、Codex、opencode の作業履歴を集めて、日報・振り返り・進捗報告を作る。日々の作業を別の場所に書き写さなくて済む。
  • 🧘

    oi-owarasero

    仕事や学習で手が止まった場面を、責めずに対話で振り返る。見えていなかった前提を見つけ、次の一歩を1つ決める。
  • 🎨

    hallmark

    AI が作ったように見えない UI を作るデザインスキル。21のテーマから選んで組み立て、AI によくある見た目になっていないかを確かめてから返す。既存コードの採点や作り直しもできる。
  • ⏱️

    i-have-adhd

    エージェントの回答を短くし、次にやることから書かせる。手順は番号付きで並べ、「お役に立てれば幸いです」のような定型文を省く。
  • 📷

    photo-abstract-editorial

    写真1枚を、元の写真・抽象的な図柄のパネル・詩的な英語タイトルを組み合わせた縦長の作品にする Codex 向けスキル。図柄は写真の構図と色の関係から作る。商用利用は不可。
  • 🦸

    superpowers

    コーディングエージェントに開発の進め方を一式教えるスキル集。いきなりコードを書かずに要件を聞き出し、設計と実装計画を確認してから、サブエージェントに作業を分けて進める。
